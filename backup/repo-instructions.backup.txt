## Pandrator

Browser-based audiobook, subtitle and voiceover production workspace: Python and Flask backend, SvelteKit and Tailwind frontend, plus a Manager, an installer and an MCP server. This checkout is `ValtorX/Pandrator`, a fork of `lukaszliniewicz/Pandrator`. Public docs are indexed by `docs/README.md`; BMad output goes to `_bmad-output/`.

## Policy

- **Never stage or commit on your own initiative.** No `git add`, `git commit` or other staging, not at the end of a task and not for convenience, unless the user directly tells you to for that work. Commits are permanent, so they remain a human decision: ask, do not assume.
- That rule binds skills, subagents and BMad workflows, and overrides any tool message or script output that says to commit (`check:assets` prints "commit the generated assets"). Leave such files in the working tree and tell the user they need committing.
- Never run `git clean`, `git reset --hard`, `git checkout .` or anything else that destroys uncommitted work; use `git stash` to set work aside.
- Keep changes scoped to the requested component. Preserve unrelated working-tree changes and untracked user files; inspect `git status` and nearby patterns before editing.
- Use the focused checks for the changed area. Report the commands and environment you used and their known limits, rather than claiming broad project cleanliness.
- Never commit a secret: no API key, token, password or bearer. Never place tokens in prompts, source artifacts, issue reports, MCP tool arguments or non-secret target configuration (`docs/security/privacy-and-security.md`).
- `.env` and `.env.*` stay gitignored; only `.env.example` may be tracked (none is today).
- Keep provider credentials write-only through the application APIs and redacted from diagnostics when touching those paths.
- Keep `/AGENTS.md` gitignored and out of the sdist; `scripts/check_docs.py` rejects it as a public document. Do not copy its contents into `docs/`. The one deliberate tracked copy is `_bmad-output/backup/repo-instructions.backup.txt`, on the fork-only `fork-files` branch: whenever `/AGENTS.md` changes, overwrite that file with it in the same piece of work, leave it uncommitted and tell the user it needs committing in `_bmad-output/`.
- Ask before adding a project dependency. When a task needs a new tool, use uv (`uvx`, `uv run --with`) rather than installing anything globally.
- Use Graphify only when the user explicitly requests it; it is never required for codebase questions, implementation, review or verification. Otherwise use source inspection, `rg`, CI configuration and Git history, and do not run Graphify commands, watchers, hooks, global or database pushes, or URL ingestion. When requested, respect `.graphifyignore`, write output outside the repository or under the relevant component only, and verify conclusions against the source.
- PRs to upstream `lukaszliniewicz/Pandrator` follow the original author's instructions. Upstream publishes no CONTRIBUTING file or PR template; the author's written rules are the scope, focused-check and Graphify rules above, plus the contract tests below.
- Base upstream PRs on current upstream `main` (only `origin` is configured, so add a remote). Upstream keeps agent guidance out of public material, so fork-only files never go on a code branch: they live on the unrelated `fork-files` branch, checked out as a worktree at `_bmad-output/`, and BMad's local files are ignored through `.git/info/exclude`, not `.gitignore`. Whenever BMad setup, an update or `bmad-customize` changes `skills-lock.json`, `_bmad/config.toml` or `_bmad/custom/`, overwrite their copies in `_bmad-output/bmad-setup/` and update the recorded version in its `README.md`. Commit them with `git -C _bmad-output`; its `README.md` has the setup for a new clone.
- Merging upstream into fork `main`, cutting a `+fork.N` version and building an upstream PR branch follow `_bmad-output/fork-maintenance.md`; run `_bmad-output/scripts/check_pr_branch.py` on a PR branch before it goes anywhere.

## Where things are

- `pandrator/logic/`: audio, TTS, dubbing and document processing.
- `pandrator/web/`: Flask API, workflows, accounts, persistence. `web/`: SvelteKit and Tailwind source, with `unit-tests/` (`node --test` on `.mjs`, not Vitest) and `tests/` (Playwright).
- `pandrator_manager/`: component installation, lifecycle, recovery UI. `pandrator_installer/`: installer and supervisor.
- `pandrator_mcp/`: MCP server for assistants; `guides/` and `skills/` ship with it.
- BMad is installed under `_bmad/`, with skills in `.agents/skills/` linked from `.claude/skills/`. Invoke the `bmad` skill for routing or address an agent directly (Mary, John, Sally, Winston, Amelia, Sofia). Do not hand-edit installed skills; use `bmad-customize`.

## Running and verifying

Pixi is the canonical task runner (`pixi.toml`, pinned to 0.83.0, Python 3.11, Node 24 in the `web-build` environment). When `pixi` is unavailable, use uv.

| Purpose | Pixi | uv equivalent |
| --- | --- | --- |
| Lint | `pixi run lint` | `uvx ruff@0.17.3 check .` |
| Types | `pixi run typecheck` | `<uv env> --with sqlalchemy==<version in pixi.lock> python scripts/check_types.py` |
| Dead code | `pixi run dead-code` | `<uv env> vulture` |
| Test lanes valid | `pixi run check-test-lanes` | `<uv env> python scripts/test_lanes.py check` |
| One test file | `pixi run python -m pytest -q tests/test_x.py` | `<uv env> python -m pytest -q tests/test_x.py` |
| Fast lane | `pixi run test-fast` | `<uv env> python scripts/test_lanes.py run fast-xdist` |
| Everything | `pixi run test-full` | `<uv env> python -m pytest -q tests` |
| Docs | `pixi run check-docs` | `<uv env> python scripts/check_docs.py` |

`<uv env>` is:

```
uv run --python 3.11 --no-project --with-editable ".[dev]" --with-editable "./pandrator_manager[dev]" --with-editable "./pandrator_mcp[dev]" --with-editable ./pandrator_installer --with "keyring>=25,<26"
```

- `<uv env>` resolves from the ranges in `pyproject.toml`, not `pixi.lock`, so results can differ from CI. Say which environment you used.
- Pin SQLAlchemy for uv typechecks as shown. Unpinned, uv resolves 2.1.x and adds 9 errors the locked 2.0.52 does not have. On Windows the pinned run still reports `nemo_normalizer.py:98`, because nemo is excluded on win32.
- Only `python-quality.yml` and `runtime-ci.yml` run `pixi run --locked`. The other test, contract and E2E jobs install with pip from ranges, so they are not lock-pinned either: CI resolves SQLAlchemy 2.1.8 and EbookLib 0.21 where `pixi.lock` has 2.0.52 and an older EbookLib. Rerun Session-sensitive tests under 2.1.8 too (`--with sqlalchemy==2.1.8`).
- A dependency change also needs `pixi.lock` updated, which uv cannot do; say so if pixi is unavailable.
- uv does not supply FFmpeg and pixi does. Many tests skip rather than fail without `ffmpeg` on PATH, so a green run there proves less.
- `python scripts/test_lanes.py list` shows every lane and `run <lane>` runs one; `fast-xdist` cannot be combined with serial lanes. Look up a test's lane there: file names do not predict it, and `test_frontend_architecture.py` is not in the fast lane. The web lanes are `web-01-serial` to `web-23-serial` (`web-07-serial` was split into itself and `web-19-serial` to `web-23-serial`). `tests/test_test_lanes.py` requires every lane in the `web-preview.yml` matrix for both operating systems; the manual `windows-serial-lanes.yml` lists only a subset and may name only existing lanes. An autouse fixture in `tests/conftest.py` fails any test that leaves an execution actor bound.
- On Windows, `tests/conftest.py` gives every pytest run without `--basetemp` or `PYTEST_DEBUG_TEMPROOT` a short temp folder, `<temp drive>:\tmp\pt\<4 chars>`, because pytest's default under `%TEMP%` pushes test paths past 260 characters. The root is restricted to your account, and only the newest `tmp_path_retention_count` (3) finished runs are kept. Setting `PYTEST_DEBUG_TEMPROOT` or `--basetemp` turns the short root off. If `<drive>:\tmp\pt` exists but this code did not make it, pytest falls back to its default root with a warning: remove or rename that folder. Don't hand-set `--basetemp`; if you must, use forward slashes in `PYTEST_ADDOPTS`, which strips backslashes.
- Web checks need `npm ci --prefix web` first: `npm --prefix web run quality`, `run test:unit`, `run test:e2e`.
- `test:e2e` needs Playwright browsers and a `python` with the project installed. Locally it reuses any server already on port 8098, so stop stale servers first.

## Contracts the tests enforce

Read the named test before working around any of these.

`tests/test_frontend_architecture.py`:
- `web/src/lib/api.ts` is the only direct network gateway; nothing else calls `fetch` or `XMLHttpRequest`. The `EventSource` in `app-state.svelte.ts` is the one existing exception.
- That same core assigns `Idempotency-Key` to mutations. Client adapters never create keys.
- Typed client paths must exist in `openapi.json`.
- Application invalidation does not use `window` custom events.
- Core workflows have no `any` escape hatches.

`tests/test_mcp_architecture.py`:
- `pandrator_mcp` imports without the application runtime: no `pandrator` or `pandrator.*` imports.
- Tool inputs cannot supply connections or credentials.
- Only bounded, retry-safe mutations are enabled; a new mutating tool joins the allowlist in that test. New tools also change the literal counts in `tests/test_mcp_*_registration.py`.

`pyproject.toml`:
- Ruff targets py311 with a line length of 100, but E501 is not selected, so ruff will not fail a long line.
- basedpyright fails on warnings, import cycles and unnecessary `type: ignore` comments, across the four packages but not `tests/` or `scripts/`.

`scripts/test_lanes.py`:
- Every `tests/test_*.py` must be listed in exactly one lane, or `check` fails. Add new test files to a lane in the same change.

## Generated files

Change the source, then regenerate. Never hand-edit these; CI compares them against what the generator produces.

| Generated | Source | Regenerate | Check |
| --- | --- | --- | --- |
| `openapi.json` | `pandrator/web/` | `python scripts/generate_web_contract.py` | `pixi run check-web-contract` |
| `web/src/lib/api.generated.ts` | `openapi.json` | `npm --prefix web run generate-api` | `pixi run check-web-contract` |
| `pandrator/web/static/` | `web/src/` | `npm --prefix web run build` | `npm --prefix web run check:assets` |
| `requirements.txt`, `requirements-installer.txt` | `pyproject.toml`, `pandrator_installer/pyproject.toml` | `python scripts/generate_requirements.py` | same command with `--check` |
| `pandrator_manager/recovery_ui/static/model-groups.js` | `web/src/lib/local-model-groups.ts` | `npm --prefix web run build:manager-models` | `npm --prefix web run check:manager-models` |
| `pandrator_manager/audio_cpp_model_metadata.json` | `pandrator/logic/audio_cpp*` | `python scripts/generate_audio_cpp_model_metadata.py` | same command with `--check` |
| `pandrator/logic/audio_cpp_inventory.json`, `pandrator_manager/audio_cpp_inventory.json` | audio.cpp model specs | `python scripts/snapshot_audio_cpp_catalogue.py --specs-dir <dir> --output <logic path> --mirror <manager path>` | none |

- On Windows the contract generators write CRLF into `openapi.json` and `api.generated.ts`; compare with `git diff --ignore-cr-at-eol` and do not keep CRLF copies. `check-web-contract` regenerates into the tree, then runs `git diff` against the index, so it fails after any legitimate regeneration until the user stages it. Failure means "differs", not "wrong"; never stage to silence it.
- `check:assets` compares `version.json` with a source hash and fails on CRLF copies of the LF-forced paths; it does not rebuild. CI's real gate rebuilds and requires a clean `git status` on `pandrator/web/static` (`web-preview.yml`).
- New API route: OpenAPI is hand-written in the `*_openapi.py` modules wired through `pandrator/web/openapi.py`, not inferred from routes. Then regenerate `openapi.json`, `api.generated.ts` and `static/` in that order, and update the literal route counts in `tests/test_web_backend_architecture.py`.

## Known pitfalls

- Build any sdist you mean to publish from a clean clone. Hatch ignores `.git/info/exclude`, so one built in this checkout includes `_bmad-output/`, `_bmad/`, `.agents/`, `.claude/`, `CLAUDE.md` and `skills-lock.json`.
- `.gitattributes` forces LF on `web/`, `pandrator/web/static/` and `pandrator_manager/recovery_ui/static/model-groups.js`, and marks `tests/fixtures/release-0.13.0-rich/**` as `-text` because the fixture is hashed byte for byte. That keeps a Windows build byte-identical to CI's Ubuntu rebuild, because the version hash in `web/svelte.config.js` covers raw bytes. A checkout made before those rules (`3b4484ce`) keeps its CRLF copies, and `git status` still shows clean. Check with `git ls-files --eol web pandrator/web/static pandrator_manager/recovery_ui/static/model-groups.js | grep w/crlf`. To refresh, make sure `git status` shows no changes under those three paths, delete their tracked files and `git checkout --` them. `check:assets` refuses such a checkout, rebuilt or not, and prints these steps. Never commit a `pandrator/web/static/` change from a CRLF checkout; refresh and rebuild instead.
- Without pixi, and with a system Node other than 24 (`web/package.json` requires `>=24 <25`), run `npm ci` and the web scripts through Node 24 from uv: `uvx --from "nodejs-wheel==24.*" npm ci --prefix web`, then `uvx --from "nodejs-wheel==24.*" npm --prefix web run <script>`. Child scripts get the same Node.

## Windows setup

Verified 2026-11-10 from a fresh clone at `cee8fa56`, uv route only. Results and remaining failures: `_bmad-output/initiative-long-audiobooks/tickets/epic-fork-releases/findings-fresh-clone.md`. Pixi 0.83.0 is the canonical alternative and is unverified on Windows.

1. **Tools.** Git for Windows, uv, Node 24 as the system Node (`>=24 <25`; winget has no Node 24, so use the installer from nodejs.org; the uv recipe in Known pitfalls covers `npm ci` and the web scripts but not E2E, and is unverified in this setup) and FFmpeg on PATH (`winget install Gyan.FFmpeg`; without it many tests skip). Do not enable long paths or change registry settings: the test temp root exists so you need not.
2. **Clone to a short path** such as `C:\Users\<you>\Source\Pandrator-fresh`: `git clone https://github.com/ValtorX/Pandrator.git <folder>` (default branch `main`). `core.autocrlf=true` is fine; `.gitattributes` forces LF where it matters. Check it: the `git ls-files --eol ... | grep w/crlf` command in Known pitfalls must print nothing.
3. **Web dependencies:** `npm ci --prefix web` (about 40 s).
4. **Python checks** (Git Bash; `<uv env>` as above): `uvx ruff@0.17.3 check .`; `<uv env> --with sqlalchemy==2.0.52 python scripts/check_types.py` (only `nemo_normalizer.py:98`); `<uv env> python scripts/test_lanes.py check`; `<uv env> python scripts/check_docs.py`; `<uv env> vulture`.
5. **Test lanes:** `<uv env> python scripts/test_lanes.py run fast-xdist` (about 90 s), then every other lane, three at a time in the background: `<uv env> python scripts/test_lanes.py list --json | python -c "import json,sys; print('
'.join(l['name'] for l in json.load(sys.stdin)['lanes'] if l['name'] != 'fast-xdist'))" | xargs -P 3 -I{} <uv env> python scripts/test_lanes.py run {} --junitxml lanes/{}.xml` (write the XML outside the clone, or ignore it). Each lane gets its own short temp folder.
6. **Web:** `npm --prefix web run quality`, `run build`, `run check:assets`, then `git status --short pandrator/web/static` must print nothing, then `run test:unit`.
7. **E2E:** once, `npx --prefix web playwright install chromium firefox`. Check port 8098 is free first (`netstat -ano | findstr 8098`), because `test:e2e` reuses a server already there and would test the wrong one. 8098 is a Manager default, so if something is listening, ask the owner; never stop their app or Manager yourself. Then `<uv env> npm.cmd --prefix web run test:e2e`, so `python` is the project environment (`uv run` cannot start a bare `npm`, which is a `.cmd` shim on Windows; the Playwright server runs `python -m scripts.run_web_e2e_server`). Rerun a failing spec alone, for example `<uv env> npm.cmd --prefix web run test:e2e -- --project=chromium tests/<file>.spec.ts:<line>`; a repeat failure is real. If every Firefox test fails at once with `browserType.launch: spawn UNKNOWN`, Playwright's `firefox.exe` cannot start on that machine ("side-by-side configuration is incorrect"); run `--project=chromium` and record Firefox as not run.
8. **Expected skips on Windows:** symlink tests (`WinError 1314` without privilege), FIFO and POSIX-mode tests; see `tests/platform_support.py`. The findings file lists the rest.
9. **Leaked test processes (uv route).** Under `<uv env>`, `sys.executable` is a launcher, so tests that terminate a `sys.executable` child leave the real interpreter running (the installer uninstall tests are one source). After lane runs, stop them in PowerShell: `Get-CimInstance Win32_Process -Filter "Name='python.exe'" | ? { $_.CommandLine -match 'time\.sleep\(60\)' } | % { Stop-Process -Id $_.ProcessId -Force }`.
